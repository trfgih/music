# Melodia

Музыкальный поиск на React и TypeScript. Можно искать треки, слушать фрагменты,
сохранять избранное и переключать тему. Интерфейс на русском языке.

Сайт: https://melodia-1foe.onrender.com/

## Запуск

Нужны Node.js 22 и pnpm.

```sh
pnpm install
pnpm dev
```

Приложение откроется на http://127.0.0.1:5173/. В Windows также можно запустить
`start.ps1` — он находит установленный Node.js и запускает Vite.

```sh
pnpm test        # тесты
pnpm typecheck   # проверка типов
pnpm build      # сборка сайта и сервера
pnpm start      # запуск сборки на порту 10000
```

`pnpm preview` позволяет посмотреть сборку на порту 4173. Для другого порта
сервера задайте переменную `PORT`.

## Как устроен проект

- `src/App.tsx` связывает поиск, подборку, избранное и плеер.
- `src/components/` — компоненты интерфейса.
- `src/hooks/` — состояние поиска, аудио, избранного и темы.
- `src/services/music.ts` делает запросы и приводит ответы каталогов к типу `Track`.
- `server/musicProxy.ts` запрашивает музыкальные сервисы, кэширует ответы и ограничивает частоту обращений.
- `server/app.ts` отдаёт собранный сайт и обслуживает API.
- `server/start.ts` запускает сервер.

Избранное, история, тема и выбранный каталог сохраняются в localStorage.
Они привязаны к браузеру, синхронизации между устройствами нет. Старое избранное
с полями `previewUrl` и `storeUrl` поддерживается.

## Музыка

По умолчанию используется [iTunes Search API](https://performance-partners.apple.com/search-api),
каталог США. Ключ не нужен. Встроенный плеер воспроизводит фрагменты, обычно
30 или 90 секунд. В списке показана длительность полной песни, а в плеере —
длительность доступного фрагмента.

В переключателе есть [Audius](https://docs.audius.co/api/). Там можно слушать
полные открытые записи, но это отдельный каталог: всех известных песен в нём нет.
Закрытые и ограниченные автором треки не получают ссылку на воспроизведение.

Аудио загружается напрямую из музыкального сервиса и не сохраняется на сервере.
Поиск задерживается на 350 мс, чтобы не отправлять запрос при каждой букве.
Предыдущий запрос отменяется, когда пользователь меняет текст или каталог.
Одинаковые запросы объединяются. Сервер хранит метаданные iTunes час,
Audius — пять минут; браузер хранит результаты пять минут.

Ограничения новых запросов на сервере общие для посетителей: 18 в минуту
для iTunes и пять в секунду для Audius. При превышении нужно немного подождать.
Доступность внешних каталогов и аудиоссылок зависит от их владельцев.

Обложки и фрагменты iTunes предоставлены Apple. Кнопки магазина взяты из
[официального комплекта](https://marketing.services.apple/itunes-identity-guidelines).
Для Audius показываются сведения о лицензии и правообладателе, если они есть
в ответе API. Иконки — lucide-react, шрифт — Manrope из Google Fonts.

## Render

Используется Web Service на тарифе Free. Настройки находятся в `render.yaml`:

- Node.js 22;
- сборка: `pnpm install --frozen-lockfile && pnpm build`;
- запуск: `pnpm start`;
- проверка сервера: `/healthz`.

Сервер слушает `0.0.0.0` и порт из `PORT`. Отдельные ключи не нужны.
Одной папки `dist` недостаточно: поиску нужны серверные маршруты `/api/music`
и `/api/discover`.

После 15 минут без посетителей бесплатный сервис засыпает. Первое открытие
после этого может занять около минуты.

## Проверка

57 тестов покрывают поиск, отмену запросов, смену каталога, сохранение избранного,
события плеера и серверные маршруты. Для опубликованного сайта проверены
загрузка подборки, поиск Apple и воспроизведение фрагмента.

Физические устройства iOS/Android и Safari отдельно не проверялись.
